# 1.0 性能底线：测量路径与真机交接

> 用正式包在 Find X9 Pro 和一台约 4GB 内存的机器上测：1248 章 EPUB 和 10MB TXT 首屏 1.5 秒内，500 页 CBZ 首页 1 秒内，滑动 P95 帧时间不超过 16.7ms，内存峰值低于 256MB；数据写进 README。

当前完成测量入口、自动判定和交接文档；**两台设备均待真机，未通过设备验收**。本环境无 adb/真机测量条件，无模拟器、Find X9 Pro 或约 4GB 手机。没有生成或推算设备数据。版本仍为 **0.9.7.1 / versionCode 35**。

## 已实现

- 被测包 `com.lyric.reader.benchmark`：隔离数据、release 衍生、debug 签名、不可调试、R8 minify/shrink、ProfileInstaller、shell profileable。这是本次「正式包」的测量口径；签名 Play/GitHub 发布包属于后续任务。
- `BenchmarkActivity` 接受 `fixture=txt|epub|cbz`、`prepare=true`、`scroll=true`；不传参数仍是原 10MiB TXT。prepare 在计时外完成生成/复制、SHA 校验、正常导入、设置重置、进度归零、解析/图片缓存清理。TXT 恰好 10,485,760 字节 UTF-8，唯一搜索词在 6MiB 处。缺书、不可读、校验或导入失败会显示 `FAILED: ...`；测试立即报告失败或在有限超时后退出。
- 冷开三项各 5 轮，`StartupMode.COLD` 杀进程；`CompilationMode.Full()` 固定完全编译。等待真实 `Lyric正文:`，漫画等待成功解码且加载层结束后的 `Lyric漫画:`，再等待 UI idle，确保 trace 覆盖既有 `reportFullyDrawn`。首屏门限使用 `timeToFullDisplayMs` 的 **MAX**；同时输出 `Lyric.ColdOpen` trace。保留产品原有骨架/停留/淡入，计入时间，不拿隐藏内容 ready 作终点。
- 文字 `PageMode.SCROLL` 为主滑动测试，每轮 30 次向上滑动；另测漫画默认 RTL 横向 pager，每轮 30 次向右滑动，无需点中央显示 chrome。均 5 轮，准备后先杀进程重开并等待正文，滑动本身才进入计时。合并五轮 **raw `frameDurationCpuMs`**，排序取 nearest-rank `ceil(N×0.95)` 的 P95，≤16.7ms；不是轮次平均数的 P95，也不是主机 JVM 时间。原有 `pageTurnFrameTiming` / `searchFirstResult` 保留，单独作为历史诊断，不替代五项 1.0 验收。
- 所有冷开/滑动 run 都记录 `@OptIn(ExperimentalMetricApi)` 的 `MemoryUsageMetric(Mode.Max)`：HeapSize、RssAnon、RssFile、RssShmem、Gpu。检查器要求每项完整 5 轮；每轮 `memoryRssAnonMaxKb + memoryRssFileMaxKb + memoryRssShmemMaxKb + memoryGpuMaxKb`，取最大值，乘 1024 / 1,000,000 得 **十进制 MB**，严格 <256MB。heap 只诊断，已属于 RSS，不能再相加。
- 该内存数是 trace 采样的 **RSS+GPU 各分项峰值之和的保守上界**，包含 graphics；分项峰值可能不同时出现，GPU 也可能与 RSS 有重叠，因此可能高估。它不是精确同步 PSS 峰值。设备若未输出 GPU 或任一分项，检查器失败，保留 trace 交新瑞补测，不能把缺失值补成 0 或凭 heap/PerfLog 勾选通过。上界超标也需要核查 trace/PSS，不能直接改用更小的 heap 数。
- 脚本另外在计时外保存包级 `dumpsys meminfo` 完整原文（含可用的 TOTAL PSS、HEAP、GRAPHICS），用于核对进程和 graphics。它是快照，不冒充峰值；不在性能 run 中轮询 dumpsys，以免扰动帧时间。进程内 250ms PerfLog sampler 和 Java heap 均不足以验收 256MB。
- `check-benchmarks.py` 的 reference / entry 都使用同一 1.0 门限，缺少任一要求、少于/多于 5 轮、无原始帧/内存分项或非法数字均失败；旧 25ms / 3000ms 入门机门限仅保留在 README 的历史表中。

指标依据：[AndroidX MemoryUsageMetric](https://developer.android.com/reference/kotlin/androidx/benchmark/macro/MemoryUsageMetric)，项目固定依赖 1.3.3；字段/单位同时核对了 [1.3.3 官方源码包](https://dl.google.com/dl/android/maven2/androidx/benchmark/benchmark-macro/1.3.3/benchmark-macro-1.3.3-sources.jar) 中的 `MemoryUsageMetric` / `MemoryUsageQuery`。

## 新瑞：电脑 + adb（首选）

1. 准备 JDK17、Android SDK35 / Build Tools35.0.0、platform-tools、Python3，拷贝仓库及上述原书，核对 SHA。两台依次测：Find X9 Pro；约 4GB，默认 Redmi A3 **4GB**（如改用其他机器，写实际型号与物理 RAM，不把内存扩展当作物理 RAM）。Macrobenchmark 要 API29+。
2. 每次只接一台，开启开发者选项/USB 调试并授权电脑。默认排版由 prepare 重置（宋体、默认字号/行段距/边距），只为文字滑动 run 切换滚动模式。两机锁定相同刷新率（建议 60Hz）、系统字体/显示缩放保持默认、三项动画缩放均 1×、关闭省电；记录温度/电量、避免发热和后台重负载，竖屏测量。脚本记录 model、incremental、RAM、API、刷新率/显示、电源、电池与动画配置，拒绝非 1×/已开启省电；仍需人工核对有效刷新率和热状态。
3. 跑下列命令。脚本会构建/安装 benchmark APK，推送两书（TXT 设备生成），执行全部 7 个测试，再复制 JSON、报告、Perfetto trace，采集计时外 meminfo 并检查门限。失败也保留已有报告；不会默认屏蔽 Macrobenchmark 的设备配置错误。

```bash
export JAVA_HOME=/home/box/jdk17
export ANDROID_HOME=/home/box/Android
export PATH="$ANDROID_HOME/platform-tools:$JAVA_HOME/bin:$PATH"
# 其他电脑换成各自真实路径；不要设置 LYRIC_LOAD_BENCH。
./gradlew assembleDebug test assembleBenchmark :macrobenchmark:assembleBenchmark
adb devices -l
export ANDROID_SERIAL='实际序列号'
export LYRIC_EPUB_FIXTURE='/workspace/epub-real/jianlai.epub'
export LYRIC_CBZ_FIXTURE='/workspace/lyric-test-500p.cbz'
TIER=reference scripts/run-benchmarks.sh benchmark-results/find-x9-pro
# 换接约 4GB 手机，更新 ANDROID_SERIAL，使用新的空目录：
TIER=entry scripts/run-benchmarks.sh benchmark-results/redmi-a3-4gb
# 两个 tier 同样严格；单独复查原始 JSON：
python3 scripts/check-benchmarks.py benchmark-results/find-x9-pro reference
```

构建产物 `app/build/outputs/apk/benchmark/app-benchmark.apk`；独立编译命令 `./gradlew :app:assembleBenchmark :macrobenchmark:assembleBenchmark`。脚本内部执行 `:app:assembleBenchmark :macrobenchmark:connectedBenchmarkAndroidTest`。无 adb 或未连接/未授权设备会明确失败，不能产生通过结果。

默认结果目录是 `benchmark-results/YYYYmmdd-HHMMSS/`（也可传空目录）。保留 `device-summary.txt`、完整 `device-properties.txt` / `device-ram.txt` / `device-display.txt`、`gradle.log`、`connected_android_test_additional_output/`（JSON/trace）、`androidTests/`（报告）、`meminfo-*.txt`、`check.txt`。不要把两台机器/多次结果合并到同一目录。meminfo 的 `TOTAL PSS` 与 `HEAP` / `GRAPHICS` 行若设备输出即保存在原文；启动失败或无此字段也应保留，不能补数。

4. 从 `check.txt` 将 EPUB/TXT/CBZ 的五轮 MAX ms 回填 README 的对应机型列；滑动写文字 P95、漫画 P95（都需 ≤16.7）；内存写五个 run 中最大 RSS+GPU 上界 MB，并附 meminfo PSS/graphics 快照（标明快照）。附实际型号/RAM、API、incremental、刷新率、条件、结果目录或可下载的原始证据链接。若任一内存分项缺失，填“未完成：缺 …”，不能改成通过。未通过的项目如实写数值/失败，保留 traces。

## 无 adb 的补充记录

在手机安装同一 benchmark APK，从 launcher 打开 `lyric`，用 USB 文件传输把两本真实书复制到 Download，经系统文件选择器正常导入。10MB TXT 可在任意有 Python3 的电脑生成后用 USB 拷贝（不需要 adb）：

```bash
python3 - <<'PY'
from pathlib import Path
line = b'Reading quietly across the paper, one sentence at a time.\n'
size = 10 * 1024 * 1024
Path('benchmark-10mb.txt').write_bytes((line * (size // len(line) + 1))[:size])
PY
```

开启 我的 → 关于 → 连点版本 **7 次** → 性能记录；每项至少五轮，默认排版/1×动画/同刷新率/无省电，每次清理解析与图片缓存并在系统应用设置中强行停止 benchmark 包，再从书架打开；可以用外部录像/秒表记录可见首屏。文字改滚动模式滑动，漫画用手势翻动，结束后同一入口“导出性能记录”分享文件。导出后可关闭性能记录。

**此路径只有人工/PerfLog 补充证据**：书架点击与 Macrobenchmark 进程启动的起点不同，秒表不能替代 `reportFullyDrawn`；PerfLog 的 250ms Java/native 采样缺 graphics，帧记录也不能替代 Macrobenchmark raw P95/PSS。README 必须标记“人工/PerfLog，非 Macrobenchmark 验收”；不能据此勾选滑动或总内存通过。仍需回到有 adb 的电脑完成正式测量。
