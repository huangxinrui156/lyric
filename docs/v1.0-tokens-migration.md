# v1.0 token migration

Authority: `design/v1.0/tokens.md`. No version, icon, label, navigation, parser, or import-flow changes.

- `ui/theme/LyricTokens.kt` contains the exact day/night palette, four complete UI type styles, radii, six spacing steps, smallest-width 600dp page-margin breakpoint, two built-in fonts, three reading presets, 640dp reading-body cap, and 150/200/300ms ease-out helpers.
- `ui/Theme.kt` supplies Material colors/type/shapes and theme-aware aliases. Primary buttons use neutral ink/paper; selectable accents remain available for accent controls. Day grain is removed entirely; night grain uses 0.03 Screen blending.
- UI call sites use tokens, including explicit button/chip/panel shapes and complete text styles. Card surfaces/strokes use the new palette. Existing component dimensions and artwork are separated from approved spacing/type tokens.
- The existing shelf empty-state item now says 「书架还空着」 at 40% of the shelf viewport, then a 16dp gap and primary 「导入书籍」 button. Its existing import callback is unchanged; there is no illustration or new flow.
- Reading defaults now use comfortable (18sp / 1.7 / 24dp / 0.5em); explicit saved overrides are preserved. The reader font menu exposes 宋体/黑体 and existing font import. The settings typography row still also lists the pre-existing built-in 等宽 option (see question 7). Previously saved monospace choices still render through the existing renderer fallback. No preset picker was added.
- `reader/LoadPresentation.kt` retains 300ms skip, minimum 300ms visibility, and 150ms fade. Skeleton color/radius use tokens. Breathing rises from 0.6 to 1.0 over the requested 1.2s and reverses, without shimmer. HEAD had 600ms legs; the explicit request's 1.2s rise takes precedence.

Exceptions and questions for 美术设计:

1. **Accent presets:** retain all six. 苔/朱 use exact day/night tokens; should 枯茶/黛蓝/灰紫/石色 retain their old hex and night lightening, or receive new pairs?
2. **Shelf switch:** HEAD actually uses **2000ms**, not 1400ms. Its reversible drawing/morph/hold/fade choreography and phase proportions remain; only easing is unified. Confirm 2000ms or supply a revised duration/choreography. Reduced motion retains its existing 200ms crossfade.
3. **Content artwork:** pending tokens preserve reader content themes, highlight swatches, comic ink/background/bar/error palette, generated covers, overlays, and page-fold shading. Which should adopt the UI palette? Engine selection/marker alpha and curl palettes remain in `core/ThemePalette.kt` as documented content-art exceptions, not Compose chrome.
4. **Exports:** `NoteExport.kt` references tokens but retains its separate export divider and pixel-based artwork/layout. Should the export divider also adopt the chrome stroke?
5. **Geometry/display:** touch targets, cover dimensions, slider/dial geometry, viewport caps, and the existing 52sp countdown are named pending values. Confirm these component dimensions and the countdown's display-type exception.
6. **Library motion:** all app-authored transitions use token ease-out; the custom reader panel uses 300ms. Material3 **1.3.1** owns `ModalBottomSheet`'s internal 300ms FastOutSlowIn tween and has no public animation-spec override (verified in the installed AAR). This dependency-internal easing remains an exception; confirm acceptance or separately scope a component/library change. No dependency upgrade or reflection workaround is introduced.
7. **Built-in 等宽:** `SettingsScreen` still offers 宋体/黑体/等宽 as built-in families; the reader sheet already uses 宋体/黑体 plus custom import only. tokens.md allows only those two families. Should the settings row drop 等宽 (keeping render fallback for already saved values)?

Runtime preference-to-dp conversions, interpolated positions, zero dimensions, layout fractions/counts, and nonvisual ViewModel polling/debounce timers are not palette/animation literals. The checker prints concrete source locations for justified exceptions, with no UI-file blanket allowlist.
