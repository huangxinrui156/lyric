# v0.3.2 — 导入诊断与整屏仿真翻页

版本：`versionName 0.3.2`，`versionCode 5`。基于 `2b24f05`。

## EPUB 导入：已复现的根因

1. **流式 ZIP 读取不兼容部分合法压缩包。** 新增 `stored-descriptor.epub`，通过不可 seek 的输出流写入 STORED 条目和 data descriptor。旧 `ZipInputStream.nextEntry()` 在读取 `container.xml` 前即抛出 `ZipException`（only DEFLATED entries can have EXT descriptor）。这与文件扩展名、SAF 路径解码无关。
2. **条目名强制 UTF-8。** 新增带 GBK 和 CP437 条目名的完整 EPUB。旧实现对 GBK 文件抛出 `IllegalArgumentException` / `MalformedInputException`。文件内容是 UTF-8，并不能保证 ZIP 条目名也是 UTF-8。
3. **XML 查询绑定了出版商的前缀写法。** 旧查询 `rootfile`、`manifest > item`、`spine > itemref` 不匹配 `c:rootfile`、`opf:manifest` 等节点；标题作者只认 `dc:`。新的 UTF-8 ZIP64 和旧编码夹具都使用不同前缀，验证按 local name 读取。
4. **授权与读取被混为一谈。** 文件夹导入使用 `require(persist(uri))`，临时授权可读时仍直接失败。文件导入虽然忽略持久授权失败，稍后打开却仍依赖原 URI，FileProvider 临时授权撤销后不能阅读。新增强制 `takePersistableUriPermission()` 抛出 `SecurityException` 的测试，验证导入和重开均成功。
5. **元数据查询与报错不充分。** provider 可能返回空 cursor、无 DISPLAY_NAME/SIZE 列、null 值，或不支持 query。旧错误信息只显示异常 message，缺少阶段、类型和完整复制入口。

这些是代码审计和可重复测试确认的问题。**没有拿到用户失败的原始 EPUB、设备日志，也没有连接 OPPO Find X9 Pro；无法断言上面哪一个就是该设备上那一次失败的唯一原因。** 四本真实下载均通过新管线，但不将其当作 ColorOS 实测结论。

## 导入管线改动

- 使用自定义 ActivityResultContract，文件选择明确为 `ACTION_OPEN_DOCUMENT`、`*/*`、`CATEGORY_OPENABLE`、多选，**不加 EXTRA_MIME_TYPES**。这样 ColorOS 把 EPUB 标为 ZIP 或厂商自定义 MIME 时也不会因过滤变灰；格式由读取后识别。目录选择为 `ACTION_OPEN_DOCUMENT_TREE`。
- 保留返回的 grant flags；仅申请实际授予的读取持久权限。捕获授权异常并继续打开流。临时授权导入时，将已经复制的源文件原子保存到 `files/sources-v1/<sha256>`，重开、重新解析、清缓存都可使用它；移出书架只删除私有副本。
- `content://` 一律经 ContentResolver 读取，不将 `msf:`、`raw:` 或 FileProvider 路径猜成物理路径。覆盖 externalstorage、media、downloads、ColorOS/Oplus authority 及无后缀、不可信 MIME。元数据只作提示，不决定能否读取；SIZE 为 null 不影响导入。
- 目录直接查询 DocumentsContract children，递归扫描、去重和检测循环；支持 ZIP、octet-stream 等 MIME、空名称，明确传播扫描错误。
- Repository 在 IO dispatcher 上复制和 SHA-256 去重，保留应用级 coroutine scope，picker 返回和页面重组不会取消导入。CancellationException 继续传播。Room 操作独立标记阶段；约束失败不会留下半导入书架行。清理缓存与导入串行，避免删除正在解析的临时文件。
- EPUB 使用复制后的 **ZipFile 中央目录**；Repository 传递现成文件，避免再复制一次。非文件源按上限复制到 cache 后打开，finally 清理。依次尝试 UTF-8、GBK、CP437，并以实际 OPF 引用验证名称，支持 data descriptor 和 ZIP64。保留 200 MiB 源文件、32 MiB 单条目、160 MiB 展开量、10,000 条目限制；它们是明确报错的资源边界，不宣称支持无限大 EPUB。
- 沿用已有 Jsoup，自动识别 BOM、XML/meta 编码，HTML 模式容错处理 XHTML、DOCTYPE、`&nbsp;`/`&copy;` 和残缺标签；XML 模式处理 container/OPF/NCX，按 local name 查找。Jsoup 不解析外部 DTD、不访问外部实体或网络。缺失导航文件时用 spine 生成目录；保留图片/字体，识别 EPUB2/3 cover 元数据并保存封面。
- `LyricImport` 的 Log.i/Log.e 覆盖 picker、授权、元数据、扫描、流复制、格式识别、ZIP/文档解析、封面、解析缓存、Room、阅读源打开。导入状态保留每个失败的 **阶段 + 异常类 + message**。完成后弹出可滚动错误对话框，提供「复制错误信息」；同一错误再次导入也会重新显示。单本失败不阻止批次中的其余书籍。

诊断示例：`[ContentResolver/读取并复制] SecurityException: provider denied read`，`[Room/插入书架] SQLiteConstraintException: ...`。真机复测可同时执行 `adb logcat -s LyricImport LyricCurl`。

## 仿真翻页：整张纸的卷曲

旧实现的问题是结构性的：ReaderCanvas 只截取正文大小的 bitmap，PageCurl 也在正文 Box 内；页眉、背景边缘、底部信息栏均在其外。手势只在 ACTION_UP 后调用 turn，动画是一条按固定进度移动的竖向曲线，不随手指。

新实现使用完整阅读 Surface 的 GraphicsLayer 截图，包含纸色、纹理、安全区域留白、章节标题、正文和时间/电量/百分比/页码。源页和目标页均为完整 bitmap。卷页覆盖层与阅读 Surface 同尺寸，位于标题和信息栏外层，截图层本身不包含卷页覆盖层和菜单。

几何按经典 Android corner-curl 构造：固定最近的上/下书角，用触点和固定角中点求折线，两个二次 Bezier 与页面边界相交；裁剪原纸面，沿折线反射原页作为背面，叠加纸背色、透印、高光和阴影；目标页单独绘制并接受投影。向前/向后使用镜像几何，文本方向保持正常。折角的反射位置等于触点，X/Y 移动都改变卷曲形状，避免分母为零。

整页手势入口把坐标换算到正文 View，页眉、底栏和页面中部也能发起拖动，保留文本长按、图片点击和菜单行为。拖动期间只预览目标，**不提交 ViewModel/Room 进度**。释放按横向位置或速度完成/回弹，ACTION_CANCEL 总是恢复；取消跨章预览时等原章正文绘制完再移除覆盖层。点击、音量键和方向键走相同的整页截图/Bezier 动画。尺寸、排版、页面退出和生命周期暂停会取消未完成预览，丢弃截图引用。

## 测试与边界

- 真实文件位于 `app/src/test/resources/epub/real/`，约 2.3 MiB，包含 Gutenberg 11、84、23950（中文）和 Standard Ebooks Austen EPUB3；下载 URL、SHA-256、大小和版权说明在该目录 README。完整保留 ZIP 内容，release APK 不携带单元测试资源。1342 EPUB3 图片版约 24 MiB，已下载验证 ZIP，未提交；其 noimages EPUB3 URL 返回 404，因此采用上述合理子集。
- `RealEpubImportTest` 在 Robolectric API 35 上经真实 ContentProvider 调用走 URI → Repository → parser → Room → 缓存/强制重载 → ReaderCanvas 排版和正文像素绘制；测试空/缺列/抛错元数据、OEM MIME、provider 授权撤销、重建 Repository、清缓存、目录递归和循环、SecurityException、坏 ZIP 和 SQLite 约束失败后的准确诊断。
- 原有 SAF 45 组合测试保留。新增 ZIP64、STORED descriptor、GBK/CP437、命名空间、BOM/DOCTYPE、HTML entities 和破损 XHTML 夹具，由 `python3 scripts/create-epub-compat-fixtures.py` 确定性生成。
- `PageCurlTest` 用 Native Graphics 检查整页页眉/页脚、两种方向、不同触点的反射几何和阴影像素；`ReaderNavigationTest` 验证移动回调、跨章取消不写进度、重组不撤销预览、完成提交及音量键入口。
- Debug 专用 `FullScreenCurlTest` 运行实际 ReaderScreen/AndroidView 和指针事件，验证整页覆盖尺寸、拖动预览、取消恢复和点击完成。Compose 1.7 检测 Robolectric 指纹时强制走不支持 RenderNode 的软件截图；该测试仅在测试内修改指纹，以 Native Graphics 执行设备的硬件截图路径，并手动驱动 RenderNode 绘制。生产代码不检测测试环境。
