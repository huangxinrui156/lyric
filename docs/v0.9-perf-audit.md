# v0.9 performance audit

Audit of `feature/0.9`, based on `fc6c1b6`, including the interrupted audit's existing uncommitted changes. Target: reading and scrolling on a 120 Hz OPPO Find X9 Pro (8.33 ms frame budget). Expected impacts below are engineering estimates, **not measured frame-time improvements**. No device was attached for this audit. UI strings, colors, launcher assets and manifest label were not changed by this audit.

## Full-screen curl failure investigation

The interrupted audit's code passed `FullScreenCurlTest` alone but reproduced the exact reported timeout when run after `ComicReaderTest`. The same pair on untouched HEAD passed in the temporary baseline checkout. Faster UI initialization changes whether background loading happens to finish during `setContent`'s idle drain.

Compose 1.7.6's installed test implementation was inspected: `waitUntil` advances its Compose test clock and sleeps; it does not drain the Android main looper. Reader loading returns from IO onto Android Main. Explicitly draining that looper fixes the pair with unchanged timeouts/assertions. A separate baseline-only diagnostic holds the existing repository parse mutex until after `setContent` returns, forcing the realistic slow-load timing without changing production code. That delayed-load diagnostic also timed out on HEAD, then passed after adding only the same looper drain. This confirms a pre-existing harness synchronization defect exposed by the audit's changed timing, rather than a production book-loading/curl regression. All baseline experiments live outside the working tree.

## Baseline Profile / R8 / Compose stability status

- **Baseline Profile:** `androidx.profileinstaller:profileinstaller:1.3.1` is available and retained. `app/src/main/baseline-prof.txt` is a conservative handwritten seed for startup, shelf, text reader/typesetting and desk. It is not a device-captured or benchmark-validated profile. No other dependency was added. Verified wildcard expansion into app methods and the benchmark APK's `assets/dexopt/baseline.prof` (5,768 bytes) / `baseline.profm` (708 bytes).
- **R8:** enabled only on the existing `benchmark` variant together with resource shrinking. Debug and release minification settings are unchanged. Room/serialization consumer rules are retained; explicit Room implementation and conservative jsoup/chardet/androidsvg keeps protect reflection. The single `NullMarked` warning suppression concerns compile-time jsoup nullness metadata. Benchmark assembly passed, including R8, resource shrinking, profile compilation and vital lint. Device import/render smoke coverage remains outstanding.
- **Compose:** Kotlin/Compose plugin 2.0.21 has strong skipping enabled by default. The stability config whitelists only immutable `java.time` values. Locator, reader settings, TOC/style values, ShelfBook, DeskSummary and FocusUi receive immutable annotations. Book/Chapter contain legacy mutable metadata and are deliberately not annotated; Kotlin collections are not globally whitelisted. Strong skipping can compare unstable inputs by identity. Generated reports in `app/build/compose-reports` confirm `StrongSkipping: true`, 264 skippable composables and 581/581 memoized lambdas. ReaderScreen, ReaderFooter, ReaderChapterHeading, DeskScreen and BookCover are skippable; Book/Chapter remain unstable. To regenerate even when compilation is up to date, use `./gradlew :app:compileBenchmarkKotlin -PcomposeReports --rerun-tasks`.

## Not done / remaining limits

- No Find X9 Pro, emulator/device macrobenchmark, Perfetto trace, allocation recording, thermal/battery measurement or p50/p95/p99 frame-time comparison was available. Improvements need confirmation on the target 120 Hz device, especially settings sheet entry, desk fling, curl, and large comic/PDF files.
- No captured Baseline Profile, release rollout or on-device R8 smoke test. Conservative keep rules deliberately leave optimization potential; narrow them only with representative import/render coverage.
- `SaveableStateHolder` restores tab state but does not retain all tab compositions. Shelf filtering/sorting and desk note filtering remain synchronous when their inputs actually change; enormous libraries/annotation sets may justify cancellable worker filtering after profiling.
- Slide/cover still allocate a full body snapshot per animated turn. Curl still needs two full-surface snapshots, gradient shaders and recording while waiting for the destination; those costs were not eliminated. Highlight band paths are still constructed during draw, though scratch objects are reused.
- Text pagination still counts the whole book in the background and retains page boundaries; eight expensive layouts are cached. Embedded text images use the existing six-entry cache plus references held by cached layouts, rather than a new global byte budget.
- Comic/PDF cache limits exclude bitmaps still referenced by visible/prefetched Compose pages and transient compressed/decode buffers. RGB_565 and aggressive recycling were deliberately avoided to preserve artwork and bitmap lifetime correctness.
- Small draw-phase allocations in shelf switching and occasional clock formatting remain; no evidence justified a larger animation rewrite. Existing paper-grain bitmaps and lazy desk layout were preserved.
- Existing design assets in the dirty tree were preserved, not created or revised for this audit. No commits or branch changes were made.
